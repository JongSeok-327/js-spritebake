# JS SpriteBake

**手元の動画から、透過スプライトシートを作成。**

[English](README.md) · [한국어](README.ko.md) · 日本語

[v1.0.0をダウンロード](https://github.com/JongSeok-327/js-spritebake/releases/tag/v1.0.0) · [編集画面](preview.png) · [シート表示](preview-sheet.png)

## 作ったきっかけ

キャラクター動画をスプライトにする作業をしていて、こういう小さなツールがあると便利だと思い、作りました。自分で使いながら少しずつ調整してきた作業用ツールですが、同じような作業をする方にも役立てばと思って公開しています。

## できること

- PC内の動画を開き、抽出する時間範囲とフレーム数を指定
- 単色背景の除去、エッジの調整、背景色のにじみ抑制
- 全フレームで共通の切り抜き範囲と倍率を使い、個別の位置も補正
- アニメーション、出力シート、個別フレーム、オニオンスキンの表示
- 隣接する重複候補の比較・除外・取り消し。結合したフレームの再生時間を維持
- 透過PNGシート、または個別PNG・再生情報・設定JSONをまとめたZIPを保存

**v1.0.0 · MIT · 実行用パッケージの追加インストール不要 · APIキー不要**

現在、編集画面の言語は韓国語です。この説明書は英語・韓国語・日本語で用意しています。公開パッケージには個人の制作動画を含めず、空の作業画面から始まります。

## 必要なもの

| 必要なもの | 詳細 |
| --- | --- |
| Python | [公式サイト](https://www.python.org/downloads/)で入手した **3.11以降**。下記のコマンドで確認してください。 |
| ブラウザー | 最新のデスクトップ版 **ChromeまたはEdge**を推奨。対応コーデックはブラウザーとOSによって異なります。まずはMP4/H.264をお試しください。 |
| PC | WindowsまたはmacOS。動画とフレームを処理するメモリーが必要です。最初は512–1024px、12–24フレーム程度を推奨します。 |

Pythonは画面用ファイルを配信するだけで、動画処理はブラウザー内で行います。**利用時にFFmpeg、Node.js、npm、Git、GPU用ソフト、有料アカウント、動画生成サービスは必要ありません。** ダウンロードや前提ソフトのインストール後は、インターネット接続なしで実行できます。

実機で検証した環境はWindows・Python 3.11・Chromeです。macOS用の起動スクリプトと手順は共通のPython・ブラウザー機能を使用していますが、**MacBook実機での検証はまだ行っていません。** Safari、Firefox、スマートフォンは現在の検証対象ではありません。

## Windowsで起動

1. Python 3.11以降をインストールします。`py`ランチャーまたは`python`コマンドを利用できるようにし、インストール後にターミナルを開き直してください。
2. リポジトリーまたはリリースのZIPをダウンロードし、**フォルダー全体を展開**します。ZIPの中から直接実行しないでください。
3. **`start.cmd`をダブルクリック**します。`py -3`、次に`python`を探して起動し、既定のブラウザーを開きます。
4. 作業中はコマンドウィンドウを開いたままにします。終了するにはそのウィンドウで **Ctrl+C**を押します。

展開したフォルダーからPowerShellで起動することもできます。

```powershell
py -3 --version
py -3 server.py
```

`py`がなく、`python`コマンドが使える場合:

```powershell
python --version
python server.py
```

既定のブラウザーで動画を読み込めない場合は、表示されたローカルURLをChromeまたはEdgeで開いてください。

## macOS / MacBookで起動

1. [python.org](https://www.python.org/downloads/)からPython 3.11以降をインストールし、`python3 --version`で確認します。
2. ダウンロードしたZIP全体を展開します。
3. プロジェクトフォルダーでターミナルを開いて実行します。

```sh
python3 --version
python3 server.py
```

作業中はターミナルを開いたままにし、終了するには **Control+C**を押します。起動スクリプトはIntelやApple Silicon専用のバイナリーに依存せず、動画のデコードはブラウザーが担当します。

ダブルクリック起動を使いたい場合は、同じフォルダーで実行権限を付けます。

```sh
chmod +x start.command
./start.command
```

その後はFinderから`start.command`をダブルクリックできます。macOSによりダウンロードしたスクリプトがブロックされた場合は、内容を確認して上記のターミナルコマンドを使用してください。システムのセキュリティ機能を無効にする必要はありません。Homebrewも必須ではありません。

## ローカルURLと起動オプション

既定のURLは **`http://127.0.0.1:8765`**です。ポートが使用中の場合は、続く19ポートから空きを探し、実際のURLを表示します。`dist/index.html`を直接開くとモジュールやワーカーが動作しない場合があるため、表示されたURLを使用してください。

```sh
# macOS用。Windowsではpython3をpy -3またはpythonに置き換えます。
python3 server.py --no-browser
python3 server.py --port 8900
```

## 基本的な使い方

1. **영상 파일 열기**（動画を開く）を押すか、動画をドラッグします。
2. **시작 / 끝**（開始・終了）と **추출 프레임 수**（フレーム数）を指定します。初期値は最初の1秒・12フレームです。歩行では1周期程度の範囲を選んでください。
3. **프레임 추출**（抽出）を押します。終了時刻を含めない等間隔の抽出です。
4. 背景色を選ぶか **원본에서 색 찍기**（元動画から色を選択）を使います。除去範囲、エッジ、色のにじみを調整し、明るい背景と暗い背景で確認します。
5. フレームを選ぶと元動画の該当時刻に移動します。前後移動、オニオンスキン、採用チェック、X/Y補正で調整します。**출력 시트**で保存時の配置を確認できます。
6. 重複候補の番号を押すと2つの姿勢を交互に表示します。**후보 제외**（候補を除外）で適用し、**되돌리기**（取り消し）で復元します。適用履歴は残り、採用チェックや位置の変更後は再判定します。
7. **PNG 시트**または **전체 ZIP 저장**で結果を保存します。後で再開する場合は、タブを閉じる前に設定も保存してください。

**설정 초기화**（設定を初期化）は、動画を開いたまま設定・採用状態・位置・結合した時間を初期値に戻し、最初の1秒を再抽出します。

元動画は、固定カメラ、全身が映る構図、武器や装飾まで収まる余白、キャラクターに含まれない均一な単色背景が適しています。ゲーム側で移動を制御する場合、その場歩きが扱いやすくなります。

## 出力ファイルと再生時間

| ファイル | 内容 |
| --- | --- |
| `*-sheet.png` | 透過RGBAスプライトシート |
| `frames/001.png`など | ZIPに含まれる個別の透過フレーム |
| `*.json` | シート座標、元の時刻、位置補正、基準点、各フレームの`durationMs` |
| `*-settings.json` | 処理設定とフレーム編集情報。動画自体は含みません。 |

重複候補は、採用中の並びで隣り合うフレームを共通座標で比較します。背景を除いたキャラクター全体と下半身の差が、両方とも閾値以内の場合に候補になります。動作の意味理解や歩行周期の自動検出ではなく補助判定です。

**重複を結合した後も同じ速度で再生するには、ゲームでも各フレームの`durationMs`を使用してください。** PNGだけでは可変の再生時間を保存できません。チェックを手動で外すとその時間も省かれ、候補の除外では直前の残すフレームに時間を加えます。**모두 포함**（すべて採用）は各フレームと基本の再生時間を復元します。

既定のピボット`(0.5, 0.9)`は出力セルの基準点であり、足を検出した位置ではありません。X/Yは出力ピクセル単位です。補助線・番号・オニオンスキンはPNGに保存されません。再開時は同じ動画を開き、設定JSONを読み込んで再抽出してください。新しいファイルには`js-spritebake` / `js-spritebake-preset`形式IDを使用し、以前の試作版の設定も読み込めます。

## プライバシーとローカル実行の安全性

- 動画はFile/Blob APIで読み込み、ブラウザーのメモリー内で処理します。**動画アップロードAPI、クラウド処理、アカウント、解析ツール、アプリのCookie、CDN、外部フォントへのリクエストはありません。**
- サーバーは **`127.0.0.1`のみにバインド**し、LAN全体には公開しません。`dist/`内のアプリ資産だけを配信し、想定外のHost/Origin、書き込みメソッド、ディレクトリー一覧、アプリ外に解決されるパスを拒否し、ブラウザー向けのセキュリティヘッダーを送ります。
- アプリとワーカーを読み込むローカルHTTP通信は発生します。保存はユーザーが要求したときに行います。出力JSONには元動画のファイル名と処理情報が含まれるため、共有前に確認してください。
- 自動保存はありません。再読み込みやタブを閉じる操作でメモリー内の編集は失われるので、設定と結果を先に保存してください。ブラウザー拡張機能、マルウェア、ブラウザー自体の通信はこのアプリの管理外です。

**ローカル実行でも、あらゆるリスクがなくなるわけではありません。** 信頼できる動画・設定を使い、Pythonとブラウザーを更新してください。この小さなサーバーは個人のローカル作業用です。ポート転送、トンネル、バインド先の変更で外部公開しないでください。Pythonの[`http.server`ドキュメント](https://docs.python.org/3/library/http.server.html)も公開運用サーバーとの違いを説明しています。対象範囲と報告方法は[SECURITY.md](SECURITY.md)をご覧ください。

## 制限とトラブルシューティング

- 2–64フレーム、最大2048pxで処理し、元動画より拡大して抽出しません。メモリーとシートサイズによる追加制限があります。大きな処理ではRAMを多く使うため、重い場合は解像度・枚数を減らしてください。
- 自動手ぶれ補正、補間、AI背景除去、動画生成APIはありません。背景と同じ色のキャラクター部分、細い髪、影、モーションブラーは元動画の改善や別途の補正が必要になる場合があります。
- MP4/MOVはコンテナーであり、対応コーデックを保証しません。読めない場合は信頼できるツールで対応コーデックに変換してください。変換ツールは同梱していません。
- 動きが同じに見える場合は、異なる元フレーム数と抽出間隔を確認してください。短すぎる範囲から多く抽出すると同じ画面が重複し、長い範囲から少数を抽出すると途中の姿勢を取り逃がします。
- Pythonが見つからない場合はインストール後にターミナルを開き直します。ポートの問題は`--port 8900`、自動でブラウザーが開かない場合は表示URLのコピーをお試しください。更新後はWindowsでCtrl+F5、macOSでCommand+Shift+Rを使用します。

## 開発とテスト

利用時にビルドや`pip`/`npm install`は不要です。Pythonテストは標準ライブラリーのみ、JavaScriptの検査はNode.js 22以降を使用します。

```sh
# Windowsではpython3をpy -3またはpythonに置き換えます。
python3 -m unittest discover -s tests -p "test_*.py"
node --test tests/core.test.mjs
npm run check
```

起動済みのサーバーに対して`node tests/browser-check.mjs http://127.0.0.1:8765`を実行すると、任意のChrome統合テストを行えます。ブラウザー内で図形の歩行WebMを生成するため、個人の動画や外部の画像は不要です。Chromeの場所が異なる場合は`SPRITE_TEST_BROWSER`を指定します。一時ファイルはGit対象外の`.qa/`に保存します。
